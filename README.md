# Personal Journal & Therapy Tracker

A private journal for weekly entries, therapy session prep and core topics. It's a React app
built with Vite and hosted on Firebase. Sign-in, data and file uploads all go through Firebase.

- **Live site:** https://gen-lang-client-0806083499.web.app
- **Firebase project:** `gen-lang-client-0806083499`
- **Repo:** https://github.com/JordanJ7/Journal-101 (deploys from `main`)

## Quick start

```bash
npm install
npm run dev        # http://localhost:5173 (Vite default); uses the real Firebase project
```

Other scripts:

| Command | What it does |
| --- | --- |
| `npm run build` | Production build into `dist/` |
| `npm run preview` | Serve the `dist/` build locally |
| `npm run lint` | Type-check (`tsc --noEmit`) |

> The dev server talks to the **live** Firestore database and Storage bucket. Anything you
> change while signed in locally changes your real journal.

## Deploying

The site is static files on Firebase Hosting. Build first, then deploy **hosting only**:

```bash
npm run build
npx -y firebase-tools@15.33.0 deploy --only hosting --project gen-lang-client-0806083499
```

Always pass `--only hosting`. `firebase.json` also has a `firestore` entry pointing at
`firestore.rules`. A plain `firebase deploy` would push those rules too and could change
who can read or write the journal data.

How caching works, from `firebase.json`:

- `index.html` and other top-level files are served with `Cache-Control: no-cache`, so a
  reload always picks up the newest build.
- `/assets/**` has hashed filenames and is cached for a year (`immutable`).

To check a deploy:

```bash
curl -sI https://gen-lang-client-0806083499.web.app/ | grep -i cache-control
```

The home-screen app picks up a new version once it's closed and reopened.

## Firebase setup

The config lives in `firebase-applet-config.json`. These web config values are public by
design; the security rules protect the data.

| Service | Detail |
| --- | --- |
| Auth | Google sign-in (popup) |
| Firestore | Named database `ai-studio-personaljournalt-bc0c2355-172c-45d5-90b0-ae6bddaf0d17`, not `(default)` |
| Storage | `gen-lang-client-0806083499.firebasestorage.app` holds photos and videos attached to entries |

**Point-in-time recovery (PITR)** is on for the Firestore database with 7-day retention. If
entries are lost or overwritten, the database can be read as it was at any minute in the
last 7 days. Do this before editing anything else, because each new save pushes older state
toward the 7-day limit.

The app also keeps a local copy of its state in `localStorage`. On a device that last had
the missing data open, check there before going to PITR.

## How things work

### Saving

Edits are marked dirty in the store and saved to Firestore in the background. If you keep
typing while a save is in flight, the entry stays dirty until a save matches its latest
version, so those edits don't get dropped. When a direct save fails, a message appears in
the app instead of the failure being ignored. The header badge shows the save status.

Week entries live in each week document's `bullets` array. The old `/weeks/*/entries`
subcollection is no longer read.

### Themes and color palettes

The theme menu in the navbar has two groups:

- **Color Palette:** Deep Espresso (the default), Nox Noir, Crimson Violet, Lavender Steel
  and Obsidian Bloom. Each re-tints the whole app in light and dark mode.
- **Classic Accent:** Amber, Blue and Emerald. These only change the accent color.

A palette works by setting `data-palette="<id>"` on `<html>`. Under that attribute,
`src/palettes.css` overrides Tailwind's neutral color scales (stone, neutral, zinc, gray,
slate), the amber scale (used as the accent), and the `--sf-*` surface variables.
Components use those variables, for example `dark:bg-(--sf-raised-dk)`, instead of
hard-coded hex colors.

To add or change a palette:

1. Edit `PALETTES` in `scripts/generate-palettes.mjs`. Each entry needs a dark color, an
   accent color, a light color, and whether text on the accent is dark or white.
2. Run `node scripts/generate-palettes.mjs`. This rewrites `src/palettes.css` and prints a
   contrast report. Keep every value at 4.5 or higher.
3. Add the id to `AccentTheme` in `src/types.ts` and to `ACCENT_THEMES` in
   `src/utils/theme.ts`.

### PDF export

The export opens a print-ready page in a new window and calls the browser's print dialog,
where you choose **Save as PDF**. For iPad, choose **Share → Save to Files** in the print
sheet.

- Photos and videos appear under the entry they belong to. A video shows a still frame
  with a "▶ Video" badge.
- The print dialog opens only after the media has loaded, or after 20 seconds.
- Entries in Recently Deleted are left out.
- On screen, the page has a toolbar with **Close** and **Save as PDF**. The home-screen app
  has no browser controls, so without the toolbar you would be stuck on the page. The
  toolbar isn't printed.

### Home-screen app (PWA)

`public/manifest.webmanifest`, the icons and the meta tags in `index.html` make the site
installable with **Share → Add to Home Screen**. There is no service worker, so the app
always loads the current deploy and doesn't work offline.

The status bar is `black-translucent` with `viewport-fit=cover`, so the page draws under
the status bar. The header pads itself with `env(safe-area-inset-top)`.

### iPhone Duo and split screen

- **Status column:** the workspace and the comments panel pad themselves with
  `env(safe-area-inset-left/right)`. On iPhone Duo that keeps content out from under the vertical
  status column on the right edge. On other devices the padding is 0.
- **Split keyboard:** a split or floating keyboard doesn't shrink the page, so an entry near the
  bottom would be typed behind it. On touch screens, `src/hooks/useKeepCaretAboveKeyboard.ts`
  scrolls the line you're typing into the top half of the screen. The `main:has(:focus)` rule in
  `index.css` adds the room to scroll into.
- **Drag in from Reminders:** in Split View, drag reminders (or any text) onto a week's
  **Journal Entries** box, and each line becomes its own entry. The app removes list markers such
  as `- [ ]`, `•` and `1.`. A drop into a text field just inserts the text there.
- Narrow windows, including Split View at half the inner display, use the phone layout with the
  bottom tab bar. The switch is CSS only, so a draft you're typing survives opening or closing the
  phone.

## Troubleshooting

| Symptom | Likely cause and fix |
| --- | --- |
| Home-screen app shows an old version | Close it fully and reopen it. `index.html` isn't cached, so a fresh launch loads the new build. |
| Entries "saved" but missing after reload | Check the save badge and any error message first. To recover, see PITR under [Firebase setup](#firebase-setup). |
| `git push` returns 403 | The GitHub token needs **Contents: Read and write** on this repo. |
| `firebase` command not found | Use `npx -y firebase-tools@15.33.0 …` instead of a global install. |
| Port 5000 in use on a Mac | AirPlay Receiver uses port 5000. Use another port. |
